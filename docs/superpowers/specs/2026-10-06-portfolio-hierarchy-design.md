# 个人网站面试信息层级优化设计

## 目标

在不覆盖现有 `4377` 预览、不伪造业务或模型结果的前提下，把个人网站收敛成一条清晰的面试阅读路径：30 秒内看懂候选人定位、代表项目、项目主导贡献与 AI 实践边界。

## 已确认决策

- 主定位：内容增长与创作者运营；AI 工具与 Agent 是差异化能力。
- 历史项目：使用“项目主导 / 我负责”表达，不写“团队成果”或“未独立核验”。
- 业务数字：保留现有数字，页面不使用削弱性免责声明；面试口径与协作边界作为准备材料。
- 技术表达：不把 HTML / CSS / JavaScript 写成个人核心技能；改为业务流程设计、Agent 规则、AI 辅助原型搭建与验收。
- 视觉方向：保留暖橙、炭色、米白，优化字体、字号、行距、首屏高度、留白和控件可发现性。
- 公开内容：不公开数据库、凭据或未验证的模型效果，不把静态案例写成生产系统。

## 结构方案

### 首页

1. 压缩首屏 Hero，降低姓名与头像装饰的视觉权重。
2. 在首屏可见区域加入项目结果带，展示 40–50 个账号、4000+ 条有效线索和 80 万元项目 GMV。
3. 代表作品继续只保留小红书业务项目与「有据」独立实践两张主卡。
4. 工作经历中的四个业务项目默认展示“问题 → 动作 → 结果 / 主导职责”摘要，详情弹窗只承载补充信息。
5. 顶部导航增加“更多作品”入口；补充作品默认可见，早期工具列表保留一个明确的展开入口。
6. About 区默认展示一行真实能力边界，具体工具列表继续作为次级内容。

### 小红书业务案例

1. 保留背景 → 职责 → 动作 → 转化路径 → 复盘顺序。
2. 统一项目主导文案：内容策略、矩阵协作、供稿标准与转化承接。
3. 业务结果直接展示，不再使用“团队成果 / 未独立核验”字样。

### AI 工作台案例

1. 默认露出完整闭环：业务问题 → 输入资料 → Agent 检索 → 原句核验 → 生成建议 → 人工确认 → 版本导出。
2. 三阶段均展示一句摘要，tab 仅用于查看详细说明；移动端改为更容易理解的纵向步骤结构或可滚动步骤栏。
3. 技术摘要改成“业务流程设计、Agent 规则、AI 辅助原型搭建与验收”，不暗示独立前端开发能力。
4. 把模型效果、真实业务收益和真实运行记录明确列为待验证；只展示字段结构示例，不伪造模型输出。
5. 任何“查看工程实现 / 查看证据”入口都必须直接打开或定位到对应内容。

## 视觉与交互原则

- 中文正文优先可读性，避免过小字号与过紧行距。
- 橙色只承担职位关键词、核心数字、当前状态和主要 CTA。
- 关键面试信息默认可见；长解释、截图说明、深层工具列表才折叠。
- 折叠入口使用明确的“展开 / 收起”语义和足够大的点击区域。
- 不引入蓝紫渐变，不改变现有暖色品牌方向。

## 验收标准

- 首页首屏能看到候选人定位、代表作品入口和至少一组业务结果。
- 项目主导贡献与数字结果在同一阅读区域内，不需要先打开弹窗才能理解。
- AI 案例默认能读懂完整工作流、人工边界和当前验证状态。
- 320 / 390 / 1440px 无横向溢出，中文字号和行距适合阅读。
- 所有本地路由、外链、折叠、tab、弹窗和键盘交互无明显错误。
- `node --test tests/site.test.mjs`、脚本语法检查和 `git diff --check` 通过。
- 新建独立预览目录与端口，现有 `4377` 预览保持不变。
